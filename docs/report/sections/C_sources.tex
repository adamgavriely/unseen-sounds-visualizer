\section{Reproducibility and sources of the numbers}\label{app:sources}
\subsection{Reproduction}\label{sec:repro}
The development record (pre-registrations, daily notes, reviews, the labelling tool) is not part of the current release, which holds only the code, the labels, the scoring and this report. It is kept in full in release v1.2.0 (\url{https://github.com/adamgavriely/MscFinalProject/releases/tag/v1.2.0}); every path below that starts with \fp{docs/history/} or \fp{docs/README.md} refers to that release.

\paragraph{Code.} Release v1.3.7 of the repository. The final system is the configuration \cfgv{config.use_shipped()}
in \fp{config.py}; in the scoring harness it is the variant \texttt{SHIP8+MD3+WW5+SL} (Appendix~\ref{app:glossary}).

\paragraph{Environment.} Python 3.11 with PyTorch 2.5.1, transformers 5.16.1, diffusers, faster-whisper, panns-inference,
easyocr and sentence-transformers (\fp{requirements.txt}). FineLAP needs transformers 4.51.3 and runs in a second
environment, called as a subprocess (variable \texttt{FINELAP\_PYTHON}); \fp{requirements_finelap.txt} pins all its
packages and is installed without dependency resolution (\texttt{pip install -{}-no-deps}), because a resolving install
upgrades PyTorch and breaks torchaudio. \fp{download_models.py} downloads every model the final system loads (about
200\,GB), including those the detectors load internally (CLAP for FlexSED, RoBERTa for FineLAP, BERT for DASM), and
applies two cache fixes the README describes. If CLAP's tokenizer files or its safetensors weights are missing,
FlexSED does not stop with an error: it gives about 0.006 for every sound and detects nothing, so a run in which all
FlexSED scores are the same means the CLAP download is incomplete. DASM's text queries are computed once with
MGA-CLAP (\texttt{T4SED\_ROOT/third\_parties/MGA-CLAP}) and cached in \fp{data/work/dasm_text_queries.pt}. With these
steps, \fp{main.py} with the shipped configuration reproduced the shipped result of development clip tg\_d088 exactly
on a fresh GPU machine (the same two pictures, times and subjects; both picture checks passed on the first try). FlexSED and DASM are imported from their own repositories, located through the
environment variables \texttt{FLEXSED\_ROOT}, \texttt{T4SED\_ROOT} and \texttt{BERT\_DIR} (see the README); the DASM
weights are loaded from the local DASM repository. Models (Hugging Face identifiers): \fp{Qwen/Qwen3.8-27B}, \fp{Qwen/Qwen3-Omni-30B-A3B-Instruct},
\fp{nvidia/audio-flamingo-next-hf}, \fp{AndreasXi/FineLAP} (revision b419aa2), \fp{CPF2/detect_any_sound},
\fp{Qwen/Qwen-Image-2512}, \fp{google/owlv2-base-patch16-ensemble}, BEATs iter3+ AS2M cpt2 and PANNs CNN14. Revisions
other than FineLAP are not pinned.

\paragraph{Hardware and running time.} One GPU with about 80\,GB of memory (an NVIDIA H200 was used; two A100 80\,GB
cards also work). Qwen-Image needs about 57\,GB in bf16, and the picture check needs the picture model and the vision
model loaded together. Preparing the listener inputs takes about five minutes per clip; each picture try takes about
20\,s.

\paragraph{Running the system on one video.}
\begin{verbatim}
python main.py --input clip.mp4 --device cuda
\end{verbatim}
This writes \fp{data/output/<clip>_augmented.mp4} (the video with the picture panel) and the intermediate files under
\fp{data/work/<clip>/}. The run first computes the per-clip model inputs the detector needs (FlexSED, BEATs and PANNs
scores, the listener answers, DASM and FineLAP scores), then runs detection, the on-screen check and the pictures.
Detection and the on-screen check run with exactly the settings of the scored results; only the picture step uses the
final picture settings. A folder of clips is processed by calling \fp{main.py} once per clip.

\paragraph{Reproducing the reported numbers.} The scoring harness reads the gold labels and the cached model outputs of
each clip and replays the pipeline's own decision functions:
\begin{verbatim}
# Table 3: final system and baselines
python benchmark/gold/final_vs_baselines.py
python benchmark/gold/final_vs_baselines_extra.py   # F1 intervals, danger sounds
# Table 4 and Figure 7: one-model baselines
python benchmark/gold/one_model_baseline/run.py --model m2d   # also qwen, qwen_av
python benchmark/gold/one_model_baseline/make_m2d_chart.py
# configuration check
python benchmark/gold/parity_check.py SHIP8+MD3+WW5+SL
python benchmark/gold/inspector_trail_export.py \
   --expect DEV=29/58/15/6/7/2/2.056 --expect TEST=24/65/23/4/15/4/2.414
# figures of the report
python docs/report/figures/make_results_figure.py
python docs/report/figures/make_beta_figure.py
python docs/report/figures/make_body_figures.py
python docs/report/figures/make_analysis_figures.py
python docs/report/figures/make_examples_figure.py <folder with media/bysig>
\end{verbatim}
The \fp{inspector_trail_export.py} command re-runs the final system with every decision logged and stops unless the counts match exactly; it
reproduces all 158 clips. The figure scripts read the result files above and \fp{docs/decision_trail/data.js}; the
example figure also needs the rendered output videos, which are not in the repository. The cached model outputs of the benchmark clips are not part of the current release (they are
large); they are in release v1.2.0, or can be rebuilt from the clips with \fp{benchmark/gold/clip_prep.py}.

\paragraph{Decision trail.} \fp{docs/decision_trail/} is a static page over \fp{data.js} (158 clips) that shows, for every
labelled sound and every candidate of the final system, each step it passed or failed, the value, the threshold and the
model answers. The logging (\fp{src/trail.py}) only records and never changes a decision.

\paragraph{Where the records are.} The development record is in \fp{docs/history/}: pre-registrations with their results
(\fp{docs/history/preregistrations/}), review panels, daily notes and analyses; \fp{docs/README.md} gives the map. The
gold labels are \fp{benchmark/gold/annotations/gold_AG.json}.
