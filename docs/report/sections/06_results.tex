\section{Results}\label{sec:results}

\subsection{Baselines}\label{sec:baselines}
Section~7 of the project proposal (``Baseline systems'') names the systems the method is compared against. All are run
on exactly the same clips and scored with exactly the same rules:
\begin{description}
  \item[Direct audio-to-image generation] draws a picture for every sound it hears, without looking at the video. It is
        implemented as the final system with the on-screen check removed: the same detection stack, listeners, display
        rules and picture model, with every surviving sound drawn. It therefore isolates the contribution the proposal
        asks about -- reasoning about what the video already shows -- but it is an ablation: its detection rules were
        chosen for the gated system and were not re-tuned for it. (Published audio-to-image models draw a whole scene
        from the soundtrack and cannot be scored per sound; Section~\ref{sec:related}.)
  \item[Audio captioning] describes the same sounds in text instead of pictures. Under the per-sound score a caption is
        right or wrong at exactly the same moments as the audio-to-image picture, so it has the same score; the
        difference between text and pictures can only be measured with viewers (Section~\ref{sec:limits}).
  \item[Show nothing] no augmentation at all: the situation of a viewer with subtitles only.
\end{description}
A generator conditioned on the video and audio that would ``generate what is not seen'' (for example MiniMax-H3) was
also raised during supervision. It produces whole new video, which the per-sound score cannot evaluate, so it was not
run as a baseline (Section~\ref{sec:limits}).

On the test set the final system finds 24 of 65 needed sounds, and half of its pictures are right. Drawing every heard
sound finds 26, but only 30\,\% of its pictures are right, and on the test set it is no better than showing nothing
($+0.227$ per clip, $[-0.386, +0.818]$, $p = 0.49$). The final system is cheaper than both: by 0.773 per clip than
direct audio-to-image generation ($p < 0.001$) and by 0.545 than showing nothing ($p = 0.041$). On the development set
the direction is the same; the difference from direct audio-to-image is smaller there ($-0.394$, $p = 0.088$), partly
because direct audio-to-image shows fewer wrong pictures per clip on that set (0.55 against 0.70). F1, which weighs a
miss and a wrong picture equally, also favours the final system on both sets.

\subsection{What the statistical tests support}\label{sec:support}
\begin{description}
  \item[Significant.] On the test set the final system costs less than direct audio-to-image generation and audio
        captioning ($p < 0.001$) and less than showing nothing ($p = 0.041$). On the development set it costs less than
        showing nothing ($p < 0.001$).
  \item[Not significant.] On the development set, the difference from direct audio-to-image generation ($p = 0.088$).
  \item[Multiple comparisons.] The four comparisons are reported without correction. With a Holm correction over the
        two test-set comparisons both stand (adjusted $p < 0.001$ and $p = 0.041$); over all four, the test-set
        difference from showing nothing becomes $p = 0.082$.
  \item[Caveat.] The test set was read after each accepted change during development, so the test numbers are a report
        on a seen set rather than a blind confirmation (Section~\ref{sec:limits}).
\end{description}

\subsection{Sensitivity to the cost of a wrong picture}\label{sec:sensitivity}
The cost of one wrong picture ($\beta$, with a missed sound fixed at 4) is the one number in the metric that only deaf
and hard-of-hearing viewers can set. A viewer study to measure it was designed but not run, so the main analysis
assumes $\beta = 2$. Figure~\ref{fig:beta} shows how the conclusions change if $\beta$ is different.

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth]{figures/beta_sensitivity.pdf}
\caption{Cost per clip as the cost of a wrong picture ($\beta$) varies, with a missed sound fixed at 4 (point estimates).
Dots mark where a system breaks even with showing nothing. On the test set the final system is cheaper than showing
nothing for every $\beta < 4.0$, i.e.\ until a wrong picture hurts as much as a missed sound (on the development set
until $\beta = 7.7$, off the chart); at $\beta = 2$ the 95\,\% interval of that difference already comes close to zero.
Direct audio-to-image generation breaks even already at $\beta = 1.7$ (test) and $3.5$ (development). The final system
is cheaper than direct audio-to-image generation for every $\beta$ above 0.2 (test) or 0.8 (development).}
\label{fig:beta}
\end{figure}

The conclusion therefore does not depend on the exact value of $\beta$. Drawing every sound is only preferable if wrong
pictures are almost free ($\beta$ below 0.2 on the test set); the final system beats showing nothing as long as a wrong
picture is judged less harmful than a missed sound. A second check weighs only on-screen pictures less
(Eq.~\ref{eq:costw}). With $w = 1$ the final system costs 1.972 (development) and 2.364 (test), against 2.169 and 3.000
for direct audio-to-image; with $w = 0$ it costs 1.887 and 2.318, against 1.887 and 2.818. So if an on-screen picture
is judged harmless, the two systems tie on the development set, and the final system still wins on the test set.

\subsection{Where the errors come from}\label{sec:errors}
Figure~\ref{fig:errors} breaks down the misses and wrong pictures of the final system, from its logged decision trail.
Most misses are sounds that were heard as candidates and then removed by a later rule -- most often because the
listeners did not confirm a weak detection. Each of these rules was accepted because, overall, it removed more wrong
pictures than real ones; the sounds it removes are the price. Six needed sounds in each set were heard by no detector
(final system, 58 and 65 needed sounds; the ceiling analysis of Section~\ref{sec:ceiling} is on an older run with 55).
Most wrong pictures on the test set show another sound (15 of 24). Section~\ref{sec:hard} explains why these errors are
hard to remove.
