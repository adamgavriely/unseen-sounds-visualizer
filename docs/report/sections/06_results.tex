\section{Results}\label{sec:results}

\subsection{Baselines}\label{sec:baselines}
The project proposal (Section 7, ``Baseline systems'') names the systems the method is compared against. All are run
on exactly the same clips and scored with exactly the same rules:
\begin{description}
  \item[Direct audio-to-image generation] generates a picture for every sound it hears, without looking at the video.
        It uses the same detector and the same picture model as the final system, so the only difference is the
        on-screen check and the display rules that depend on it. This isolates the contribution the proposal asks
        about: reasoning about what the video already shows. (Published audio-to-image models draw a whole scene from the
        soundtrack and cannot be scored per sound; Section~\ref{sec:related}.)
  \item[Audio captioning] describes the same sounds in text instead of pictures. Under the per-sound score a caption is
        right or wrong at exactly the same moments as the audio-to-image picture, so it has the same score; the
        difference between text and pictures can only be measured with viewers (Section~\ref{sec:limits}).
  \item[Show nothing] no augmentation at all: the situation of a viewer with subtitles only.
\end{description}
The supervisor also suggested a generator conditioned on the video and audio that would ``generate what is not seen''
(for example MiniMax-H3). It produces whole new video, which the per-sound score cannot evaluate, so it was not run as a
baseline (Section~\ref{sec:limits}).

On the test set the final system finds 24 of 65 needed sounds and half of its pictures are right. Drawing every heard
sound finds 26, but only 30\,\% of its pictures are right, and on the test set it is no better than showing nothing
($+0.227$ per clip, $[-0.386, +0.818]$, $p = 0.49$). The final system is significantly cheaper than both: by 0.773 per
clip against direct audio-to-image generation ($p < 0.001$) and by 0.545 against showing nothing ($p = 0.041$). On the
development set the direction is the same; the difference from direct audio-to-image is smaller there ($-0.394$,
$p = 0.088$) because the detector heard more of the needed sounds on that set.

\subsection{What the statistical tests support}\label{sec:support}
\begin{description}
  \item[Tested and significant.] On the test set the final system costs less than direct audio-to-image generation and
        audio captioning ($p < 0.001$) and less than showing nothing ($p = 0.041$). On the development set it costs less
        than showing nothing ($p < 0.001$).
  \item[Not significant.] On the development set, the difference from direct audio-to-image generation ($p = 0.088$).
  \item[Caveat.] The test set was read after each accepted change during development, so the test numbers are a report
        on a seen set rather than a blind confirmation (Section~\ref{sec:limits}).
\end{description}

\subsection{Sensitivity to the cost of a wrong picture}\label{sec:sensitivity}
The weight of a wrong picture relative to a missed sound ($\beta$) is the one number in the metric that only deaf and
hard-of-hearing viewers can set. A viewer study to measure it was designed but not run, so the main analysis assumes
$\beta = 2$. Figure~\ref{fig:beta} shows how the conclusions change if $\beta$ is different.

\begin{figure}[h]
\centering
\includegraphics[width=\linewidth]{figures/beta_sensitivity.pdf}
\caption{Cost per clip as the cost of a wrong picture ($\beta$) varies, with a missed sound fixed at 4. Dots mark where a
system breaks even with showing nothing. On the test set the final system is cheaper than showing nothing for every
$\beta < 4.0$, i.e.\ until a wrong picture hurts as much as a missed sound (on the development set until $\beta = 7.7$,
off the chart). Direct audio-to-image generation breaks even already at $\beta = 1.7$ (test) and $3.5$ (development).
The final system is cheaper than direct audio-to-image generation for every $\beta$ above 0.2 (test) or 0.8
(development).}
\label{fig:beta}
\end{figure}

The conclusion therefore does not depend on the exact value of $\beta$. Drawing every sound is only preferable if wrong
pictures are almost free ($\beta$ below 0.2 on the test set); the final system beats showing nothing as long as a wrong
picture is judged less harmful than a missed sound. A second check weighs only on-screen pictures less
(Eq.~\ref{eq:costw}): with $w = 1$ or $w = 0$ the final system costs 1.972 or 1.887 (development) and 2.364 or 2.318
(test).

\subsection{Where the errors come from}\label{sec:errors}
Figure~\ref{fig:errors} breaks down the misses and wrong pictures of the final system, from its logged decision trail.
Most misses are sounds that were heard as candidates and then removed by a later rule -- most often because the
listeners did not confirm a weak detection. Each of these rules was accepted because, overall, it removed more wrong
pictures than real ones; the sounds it removes are the price. Six needed sounds in each set were heard by no detector.
Most wrong pictures on the test set show another sound (15 of 24). Section~\ref{sec:hard} explains why these errors are
hard to remove.
