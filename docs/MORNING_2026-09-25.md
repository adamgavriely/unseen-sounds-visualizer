# While you were away — short version

## 1. The TEST check of the timing fix: a tie
- First I checked that the new code changes nothing when its switches are off. It matched exactly.
- On the 60 TEST clips, the fix neither helped nor hurt: F1 0.40 → 0.38, and the range crosses zero.
- **By the rule we wrote before the run, the result is "inconclusive".** The fix stays (the trace proves
  it was a real bug). Its gain is reported as "seen on DEV only".
- What changed on TEST, sound by sound:
  - Onset fix: +1 bark, −1 alarm. The alarm was a case where the old code was right to move the start earlier.
  - No 8-second limit: +1 church bell, −1 chainsaw. The chainsaw picture is on screen the whole time;
    our score only counts picture *starts*, so it counts as missed.
- **New problem:** without the limit, 4 of 15 pictures stay more than 2 s after the sound ends (worst:
  an ice-cream truck, 12 s). The fix is an end rule that follows the detector's own sound level — to
  test on DEV, never a fixed number of seconds.

- Honest notes: the two TEST runs used different GPU cards; that changed 1 gate decision in 60 clips.
  And the new picture plan (V3) shows about 1 extra wrong picture per 25 DEV clips (details below).

## 2. Fair comparison against "draw everything"
I gave the "draw everything" version the same timing fix. Our gate still wins on precision, false
pictures and viewer cost (all significant). F1 is still a tie.

## 3. Pictures
- The new picture plan (V3) **made things up** (a sword for a whoosh, a police car for a plain siren).
  I found this by reading the text before any picture was drawn.
- The panel and I built **V3.1**: the scene may only add a word in front of what was heard ("car door",
  "farm vehicle"). A word list blocks kinds the audio never heard. No invented people.
- V3.1 is tested on 30 fresh clips, because its rules were written from the first 50.

## 4. The AI judge — now trustworthy
- It looks at the pictures itself. Its reference comes only from your labels, not from our models.
- It passes both trust checks clearly on all 139 clips. Asked twice, it gives the same score 59 of 60 times.
- What it says about **today's system** (DEV, 49 clips): a **tie** with both "draw everything" and
  text captions. It likes our gate on clips where the sound's source is on screen (we correctly show
  nothing). It likes our pictures least on off-screen clips — the clips this project is for.
- (On the older 139-clip run, which still used the old timing, we beat "draw everything". That is old
  data, so it's only background.)
