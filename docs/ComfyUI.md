# ComfyUI: what we want, what we have, and what is still broken

Status as of 2026-09-23 evening. Paused here; this file is the handover to whoever picks it up.

---

## 1. What we want

The supervisor suggested ComfyUI **as a GUI and wiring layer for the pipeline**, not as an image
generator. (An earlier note in `docs/comfyui_assessment.md` assessed it as a generator and concluded
"not worth it" — that answered the wrong question and is superseded.)

The goal is a **thesis/defence artefact**, explicitly NOT a replacement pipeline:

* the seven stages visible as connected boxes — the thesis's Figure 1, made live;
* **one switch** that turns the cross-modal gate off, so a committee can watch the wrong pictures
  appear on the same clip;
* it must accept **any video Adam chooses**, not only clips the benchmark has already seen;
* every number in `docs/prereg_v4.md` keeps coming from `benchmark/run_protocol.py`. The graph never
  becomes the thing that produces results.

A full migration (graph replaces `pipeline.py`) is deliberately out of scope: it would have to
reproduce `test_final_v30` exactly before any result could be trusted, which is a week of work and a
real risk to results that are already final.

## 2. What we have — working and verified

### The pipeline as nodes — DONE

`comfyui_nodes/__init__.py` — eight thin classes, each calling the function `src/pipeline.py`
already calls. No logic, threshold or model choice is duplicated.

    MscSystem             0 · gate ON = ours, OFF = blind baseline
    MscLoadVideo          1 · load video + extract audio
    MscSceneUnderstanding 2 · what is on screen
    MscTranscribe         3 · speech recognition
    MscDetectEvents       4 · sound detection + the two vetoes
    MscCrossModalGate     5 · the cross-modal gate
    MscGeneratePictures   6 · generate pictures
    MscComposite          7 · composite beside the video

Our own objects (`AudioEvent`, `SceneContext`, `AugmentationSpec`) pass between nodes unchanged as
custom types (`MSC_MEDIA`, `MSC_SCENE`, `MSC_EVENTS`, `MSC_SPECS`, `MSC_CFG`) — ComfyUI allows any
Python object as a custom type, so there is no serialisation layer.

### Unseen videos — DONE, PROVEN

FlexSED reads a cache keyed by clip name, so a new video had none. `comfyui_nodes/flexsed_worker.py`
computes it in a subprocess (the FlexSED repo needs its own `sys.path` and working directory, which
would be destructive inside a long-running server). Verified: a clip copied to a fresh name ran the
whole chain in **78 s on an H200**, with the worker producing `(215, 400)` scores on demand.

### End-to-end run outside ComfyUI — DONE

`comfyui_nodes/smoke.py` runs the eight nodes in order. This is the test that matters, because
ComfyUI only calls these classes.

    [1/7] load video + audio  0.2s   [2/7] what is on screen 18.5s   [3/7] speech 1.9s
    [4/7] sound detection    53.4s   [5/7] gate 0.1s   [6/7] pictures   [7/7] composite 2.7s

## 3. What is broken — THE BLOCKER

**The ComfyUI job was OOM-killed.** From `logs/comfy_30990119.err`:

    Loading weights:  66%|######    | 783/1184
    slurm_script: line 39: 3837448 Killed   python comfyui_nodes/comfy_start.py ...
    slurmstepd: error: Detected 1 oom_kill event in StepId=30990119.batch.

The graph ran as far as stage 5, began loading Qwen3.8-27B, and exceeded the job's `--mem=96G`.
That is why the page stopped responding.

**This is a resource setting, not a design flaw** — `smoke.py` runs the identical chain successfully
in a job with the same memory. The difference is that the ComfyUI server process is already holding
its own runtime when the VLM loads. **First thing to try: `--mem=256G` in `slurm/job_comfy.sh`, and
a partition that can grant it.**

### Also unresolved

* **Adam could not see the graph.** ComfyUI opens on its own stock text-to-image example (Load

  the Workflows sidebar → `MscProj_demo`. Whether that sidebar entry appears for him was never

## 4. The five obstacles already solved (do not re-solve these)

1. **ComfyUI needs torch >= 2.7; the project is validated on 2.5.1.** Its mandatory `comfy_kitchen`
   registers custom ops annotated `stride: list[int]`, which older `torch.library.infer_schema`
   rejects. Every ComfyUI tag back to v0.24.0 has this dependency, so there is no version that
   avoids it. **Solution: `comfyui_nodes/comfy_start.py`** teaches the existing torch the builtin
   generic spellings (`list[int]` IS `typing.List[int]`) before ComfyUI imports. The project's torch
   is never upgraded — every number in the preregistration was produced on it.
2. **Two torch installs collided** (`Allocator backend parsed at runtime != at load time`, then
   `libtorch_global_deps.so: cannot open shared object file`). **Solution: `~/comfy_deps` holds only
   NON-torch packages.** torch and torchvision must resolve to `msproj`. Verify with:
   `PYTHONPATH=$HOME/comfy_deps python -c "import torch; print(torch.__file__)"` → must contain
   `miniconda`.
3. **ComfyUI changes the CUDA allocator after torch has loaded.** Solution: `--disable-cuda-malloc`.
4. **triton needs a GPU.** Solution: run as a SLURM job (`slurm/job_comfy.sh`).
5. **Missing frontend.** Solution: `pip install --target ~/comfy_deps --no-deps
   comfyui-frontend-package comfyui-workflow-templates comfyui-embedded-docs`.

## 5. Two bugs found in our own demo code (both fixed)

1. **Gate OFF produced an identical video.** `gate_enabled` only disabled the rule-based gate; the
   visibility decision lives in `reason.decide_subjects`. `benchmark/run_protocol.py` sets **five**
   flags for the blind arm — `GATE_ENABLED`, `DEPICTION_REASONING`, `VLM_VISIBILITY`,
   `SPEECH_CONTEXT`, `RENDER_MODE`. All five now live in `MscSystem`.
2. **`RENDER_MODE` was guessed wrong.** It was set to `"side"` for our arm; the protocol uses
   `"full"` for **both** arms. The demo would have rendered our side in a mode nobody measured.
3. The flags also had to move **upstream of every stage** — ComfyUI caches and may execute out of
   order, so flags set inside a later node would arrive after earlier nodes had read them. That is
   why `MscSystem` exists and why every node takes `cfg`.
